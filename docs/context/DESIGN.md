# 界面设计规范

状态：初版（2026-11-11），只定基础规则；视觉风格、配色、页面结构待产品用途确定后补充。CSS 与组件写法见 [开发规范的组件与样式](DEVELOPMENT.md#组件与样式)。

## 基础

- 组件外观与动效以 [HeroUI v3](https://heroui.com/) 为准，使用其默认主题；主题定制（品牌色、圆角、字体）待定，定制时只改主题变量，不逐个组件覆盖样式。
- 同时支持浅色与深色模式（是否提供手动切换待定），颜色只用主题语义类。
- 图标统一用 Lucide，同一区域内图标尺寸一致。

## 交互底线

- 所有耗时操作（请求、提交、导出）有加载态，结束后明确告知成功或失败，不静默结束。
- 后到的数据不突然插入：能预知形状的区块先显示骨架，数据到达后原地淡入；切换时原地变骨架而不是先清空。
- 状态切换不改变布局尺寸，避免页面跳动。
- 左右留白、边距对称；文字容器与图标、按钮在行内竖直居中。
- 描边与阴影不被滚动区或裁剪容器切掉。
- 文案通俗、简短；标题能看懂就不加副标题。
- 有风险的操作（删除、覆盖）才需要确认；其他修改尽量即时生效。

## 动效

- 组件交互（悬停、按下、展开、弹层出入）用 HeroUI 自带动效，不另做。
- 页面与区块入场：淡入加 4–8px 位移，200–300ms，`easeOut`；退场比入场更快。
- 高度变化只在内容变化处做一次过渡，外层跟随，不多层追赶。
- 遵守系统“减少动效”设置：减少时取消位移，只保留或取消淡入（Motion 用 `useReducedMotion` 或 `MotionConfig reducedMotion="user"`）。
