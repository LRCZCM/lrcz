## 纯前端项目

- 状态：已确认。
- 确认日期：2026-11-11。

## 技术栈

- 状态：已确认。
- 确认日期：2026-11-11。
- 决定：React + Vite + TypeScript，组件库 HeroUI（v3），样式 Tailwind CSS（v4，HeroUI v3 的要求），图标 Lucide，动效库 Motion。依赖用途见 [开发规范的依赖](DEVELOPMENT.md#依赖)。
- 理由：HeroUI、Tailwind、Lucide 与动效库由用户指定；TypeScript 用于在编译期发现错误、便于长期维护。动效库选 Motion（原 Framer Motion），因其是 React 生态最常用的动效库，覆盖入场、退场、布局过渡与手势。
- 来源：用户初始化项目时指定组件库、样式、图标与“加一些动效库”；TypeScript 与 Motion 的具体选择为初始化时的建议，用户如有异议可替换。

## 代码检查与格式化

- 状态：已确认。
- 确认日期：2026-11-11。
- 决定：沿用 Vite 模板自带的 oxlint 做代码检查，Prettier（含 Tailwind 类名排序插件）做格式化；`npm run check` 为提交前完整检查。
- 理由：oxlint 速度快、零配置可用；Prettier 统一格式，避免 diff 中混入格式改动。
- 来源：项目初始化时按“前端项目要规范、可持续开发”的要求确定。

## LCML 使用手册

- 状态：已确认。
- 确认日期：2026-11-11。
- 决定：使用手册以 Markdown 写在公开发布仓库 `LRCZCM/LCML-release` 的 `docs/manual/`，网站打开页面时读取并渲染（与更新日志相同，GitHub 失败改走 jsDelivr），路由 `/lcml/manual`（首页，读 README）与 `/lcml/manual/<文件名>`（各章）；LCML 产品页顶栏有“使用手册”入口。章节顺序取自 README“## 目录”中的链接列表，分组以目录里的“### 分组名”为准，README 未写分组时用代码中的默认分组（开始、账号与皮肤、下载、实例、排错与工具、设置与帮助）。Markdown 用 `marked` 解析成标记后由自己的组件渲染，不执行文中的 HTML。界面按 `.local/drafts/lcml/manual.html` 设计稿。
- 来源：用户提出手册写在 GitHub 公开仓库、以后只更新 MD，网页读取后渲染；设计稿经用户确认后要求按规范做进项目（2026-11-11）。`marked` 为实现时的建议，随设计稿一并确认。
